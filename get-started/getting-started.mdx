This guide sets up **[doubt-bot](https://github.com/Doubt-Productions/doubt-bot)** locally. The legacy [Doubt-Discord-Bot](https://github.com/Doubt-Productions/Doubt-Discord-Bot) repo is not required unless you are running the Mongo→Postgres migrator against production Mongo data.

## Prerequisites

- **Node.js** 18 or newer
- **Yarn** 1.x (declared in `package.json`; Corepack works)
- **PostgreSQL** 14+ — local install, Docker, or a managed instance
- **Discord application** — [Discord Developer Portal](https://discord.com/developers/applications)
- **Access** to the private `doubt-bot` repository (contact Doubt Productions if you need an invite)

## Step 1: Clone and install

```bash
git clone git@github.com:Doubt-Productions/doubt-bot.git
cd doubt-bot
cp .env.example .env
yarn setup
```

`yarn setup` installs dependencies, runs `prisma generate`, and applies migrations with `prisma migrate dev` (development).

For production-style installs:

```bash
yarn setup:prod
```

That runs `yarn --omit=dev`, `prisma generate`, and `prisma migrate deploy`.

## Step 2: Configure environment

Edit `.env`. Minimum values:

```env
DISCORD_TOKEN=your_bot_token
DISCORD_CLIENT_ID=your_application_id
DISCORD_GUILD_ID=your_test_guild_id
DEVELOPER_DISCORD_IDS=your_discord_user_id
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/doubt_bot
NODE_ENV=development
```

See [Configuration](/get-started/configuration) for every variable.

<Warning>
Never commit `.env`. It contains secrets.
</Warning>

## Step 3: PostgreSQL

### Option A: Docker Compose (bundled in doubt-bot)

From the bot repository root:

```bash
docker compose up -d db
```

The sample `docker-compose.yml` starts PostgreSQL 16 and exposes it to the `app` service. Point `DATABASE_URL` at your host or use the compose network URL when running the `app` service.

### Option B: Local or managed Postgres

Create a database (for example `doubt_bot`) and set `DATABASE_URL`:

```env
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/doubt_bot
```

Apply schema:

```bash
yarn prisma:generate
yarn prisma:migrate:dev    # development
# or
yarn prisma:migrate:deploy # staging/production
```

<Note>
Production and staging should use **`prisma migrate deploy`**, not `db push`. See the [Engineering Guide](/reference/engineering-guide#prisma-migrations).
</Note>

## Step 4: Discord application

1. Create or open an application in the [Developer Portal](https://discord.com/developers/applications).
2. **Bot** → reset/copy token → `DISCORD_TOKEN`.
3. Copy **Application ID** → `DISCORD_CLIENT_ID`.
4. Enable **Privileged Gateway Intents** as needed:
   - **Server Members Intent** — welcome auto-roles, member-dependent features
   - **Presence Intent** — only if you add presence-dependent features later
   - **Do not** enable **Message Content Intent** — the bot is slash-first and AFK uses mentions/metadata only.
5. **OAuth2 → URL Generator** — scopes `bot`, `applications.commands`; invite to your test guild.
6. Copy the guild ID → `DISCORD_GUILD_ID` (used for guild-scoped command registration in development).

## Step 5: Run the bot

Development (tsx + watch via `yarn dev` / `yarn watch`):

```bash
yarn dev
```

Production build:

```bash
yarn build
yarn start
```

On success you should see discordx command import logs and `Logged in as …` from `src/events/ready.ts`.

## Step 6: Verify

1. In Discord, run `/ping` and `/help`.
2. Run tests (no live Discord or Postgres required for most regression tests):

```bash
yarn test
```

3. Optional: `yarn lint` (Biome).

## Migrating from the legacy JS bot

If you are cut over from [Doubt-Discord-Bot](https://github.com/Doubt-Productions/Doubt-Discord-Bot) MongoDB:

1. Apply Postgres migrations first: `yarn prisma:migrate:deploy`.
2. Set `MONGO_SOURCE_URL` (or `SOURCE_DATABASE_URL`) to the **read-only** legacy Mongo URI.
3. Dry run: `yarn migrate:mongo:dry-run`
4. Apply: `yarn migrate:mongo`

Details: [Engineering Guide — Mongo→Postgres migration](/reference/engineering-guide#mongopostgres-data-migration).

## Common issues

### Slash commands missing

- Confirm the bot is in the guild and has `applications.commands` scope.
- After code changes, restart the bot so `bot.initApplicationCommands()` runs on ready.
- Do not set `CLEAR_GUILD_COMMANDS_ON_BOOT=true` unless you intentionally wipe guild commands once.

### Database connection errors

- Check `DATABASE_URL` reaches Postgres (host, port, database name, credentials).
- Run `yarn prisma:migrate:status` to confirm migrations applied.

### BotStaff / staff commands deny everyone

- Populate `BotStaff` via `/botstaff add` or the Mongo migrator before expecting staff-only gates to pass.
- Apply migrations **before** staff rows or `/botstaff` writes. See [Security — BotStaff cutover](/security#global-bot-staff-acl).
