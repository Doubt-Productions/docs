Configuration for **[doubt-bot](https://github.com/Doubt-Productions/doubt-bot)** is environment-driven. Copy `.env.example` to `.env` and edit locally; do not commit secrets.

There is no `src/config.js` in the TypeScript rewrite — developer IDs, Discord credentials, and the database URL all come from `.env` (loaded via `dotenv` in `src/main.ts`).

## Required variables

| Variable | Description |
|----------|-------------|
| `DISCORD_TOKEN` | Bot token from the Discord Developer Portal |
| `DISCORD_CLIENT_ID` | Application (client) ID |
| `DISCORD_GUILD_ID` | Primary guild ID used during development and guild command registration |
| `DATABASE_URL` | PostgreSQL connection string for **runtime and Prisma CLI** |
| `DEVELOPER_DISCORD_IDS` | Comma-separated Discord user IDs with developer access |

Example:

```env
DISCORD_TOKEN=…
DISCORD_CLIENT_ID=…
DISCORD_GUILD_ID=…
DEVELOPER_DISCORD_IDS=123456789012345678,987654321098765432
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/doubt_bot
```

Developers are parsed in `src/constants/developers.ts`. An empty or missing list blocks **developer-only** commands such as `/botstaff`.

## Optional variables

| Variable | Description |
|----------|-------------|
| `NODE_ENV` | `development` or `production` (affects logging expectations; default `development` in `.env.example`) |
| `ERROR_LOG_CHANNEL_ID` | Channel ID for error reporting (when wired in your deployment) |
| `CLEAR_GUILD_COMMANDS_ON_BOOT` | Set `true` only for **one-time** guild command cleanup — not normal boots |
| `MONGO_SOURCE_URL` | Read-only Mongo URI for `yarn migrate:mongo` from legacy Doubt-Discord-Bot |
| `SOURCE_DATABASE_URL` | Alias for `MONGO_SOURCE_URL` |

### Mongo source (cutover only)

Legacy production data lives in MongoDB on [Doubt-Discord-Bot](https://github.com/Doubt-Productions/Doubt-Discord-Bot). The TypeScript bot stores runtime data in Postgres. For a one-time import:

```env
DATABASE_URL=postgresql://…/doubt_bot
MONGO_SOURCE_URL=mongodb://…/doubt_legacy
```

Run migrations on Postgres **before** `yarn migrate:mongo`. See [Engineering Guide](/reference/engineering-guide#mongopostgres-data-migration).

## Developer access

Users listed in `DEVELOPER_DISCORD_IDS`:

- Run **`/botstaff`** (`add`, `remove`, `list`, `migrate`)
- Always pass **staff-only** guards (same as a `BotStaff` row)
- Receive display-only **`bot-staff`** badge sync on relevant paths (see `badgeService`)

Developer-only gates use the `@Guard(DeveloperOnly)` decorator in `src/guards/accessGuards.ts`.

## Global bot staff

Cross-guild bot staff is stored in PostgreSQL (`BotStaff` model) and managed with **`/botstaff`** (developers only). Staff-only commands use `@Guard(StaffOnly)` — privilege comes from the **`BotStaff` table**, not guild roles and **not** from holding the `bot-staff` badge.

| Who | Staff-only access |
|-----|-------------------|
| IDs in `DEVELOPER_DISCORD_IDS` | Always allowed |
| Row in `BotStaff` (`discordId`) | Allowed |
| Everyone else | Denied (fail-closed) |

The reserved badge key is **`bot-staff`** (🛡️ Bot Staff). It is synced when staff are added or removed; it is **display-only**. `/badge` cannot create, update, or delete reserved keys or lookalikes that normalize to `bot-staff`.

<Warning>
Do not deploy with an empty `BotStaff` table and expect staff-only commands to work for guild moderators. There is no fallback to legacy `moderation.staffRoles` in doubt-bot.
</Warning>

### BotStaff cutover checklist (Postgres)

Order matters — schema before data before badge sync:

1. Deploy doubt-bot build that includes the current Prisma schema.
2. Run **`yarn prisma:migrate:deploy`** (or `yarn setup:prod`) so `BotStaff`, `Badge`, and related tables exist.
3. **Import staff rows:**
   - **From legacy Mongo:** run `yarn migrate:mongo` (includes BotStaff and badge sync), **or**
   - **Manually:** each developer runs **`/botstaff add <user>`** for every global staff member.
4. Optional maintenance: **`/botstaff migrate`** re-syncs the 🛡️ badge for all existing `BotStaff` rows (does **not** import legacy `staffRoles` from config).
5. Confirm with **`/botstaff list`**.

Legacy JS operators who still have `moderation.staffRoles` in `config.js` on Doubt-Discord-Bot should finish staff migration **before** cutover using that bot's `/botstaff migrate`, or rely on the Mongo migrator's BotStaff import — not the TypeScript `/botstaff migrate` subcommand.

See [Security](/security#global-bot-staff-acl) and [Database — BotStaff](/reference/database#botstaff).

## Docker

The sample `docker-compose.yml` in doubt-bot passes:

- `DISCORD_TOKEN`, `DATABASE_URL`, `DEVELOPER_DISCORD_IDS`, `NODE_ENV`, `CLEAR_GUILD_COMMANDS_ON_BOOT`

Build and run the `app` service after `db` is healthy, or point `DATABASE_URL` at your existing Postgres server when deploying outside compose.

## Slash-only / intents

The discordx client in `src/bot.ts` does **not** request `GatewayIntentBits.MessageContent`. Keep Message Content Intent **disabled** in the Developer Portal unless you intentionally change AFK architecture.

AFK clearing and mention notifications use `messageCreate` with `message.mentions` — not guild message body text.
