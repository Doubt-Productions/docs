Technical overview of **[doubt-bot](https://github.com/Doubt-Productions/doubt-bot)** — TypeScript, ESM, discordx decorators, Prisma on PostgreSQL.

## Startup flow

Entry point: `src/main.ts`

```
1. dotenv config()
2. setupGlobalErrorHandlers()
3. importx — load src/{events,commands,components}/**/*.{ts,js}
4. bot.login(DISCORD_TOKEN)
5. Optional: CLEAR_GUILD_COMMANDS_ON_BOOT guild command wipe
6. errorHandler.setClient(bot)
7. SIGINT/SIGTERM → closePrismaConnection()
```

Development uses `src/dev.ts` (tsx) with file watching via `yarn watch`.

The discordx `Client` is defined in `src/bot.ts`:

- **Guild commands** — `botGuilds` resolves all cached guild IDs
- **Intents** — Guilds, GuildMembers, GuildMessages, GuildMessageReactions, GuildVoiceStates
- **No Message Content Intent**

On ready (`src/events/ready.ts`):

- `bot.guilds.fetch()`
- `ensureReservedBadges()`
- `bot.initApplicationCommands()`
- Rotating activity status

## Command model

Commands are classes with `@Discord()`, `@Slash()`, `@SlashGroup()`, and `@Category()` under:

```
src/commands/categories/
├── administration/   badge.ts, botstaff.ts
├── economy/          bal, beg, deposit, economy, rob, withdraw
├── general/          afk.ts, rank.ts
├── management/       setup.ts
└── utility/          help.ts, info.ts, ping.ts, profile.ts
```

`src/commands/slashes.ts` re-exports category modules for the importer.

Guards (`src/guards/accessGuards.ts`, `src/utils/guildGuards.ts`):

- `DeveloperOnly` — `DEVELOPER_DISCORD_IDS`
- `StaffOnly` — developer **or** `BotStaff` Postgres row
- `GuildOnly`, `ManageGuildOnly` — guild and Manage Server checks

## Events

discordx `@On` / `@Once` handlers in `src/events/`:

| Module | Event | Role |
|--------|-------|------|
| `ready.ts` | `ready` | Commands sync, badges, status |
| `interactionCreate.ts` | `interactionCreate` | discordx dispatcher |
| `guildMemberAdd.ts` | `guildMemberAdd` | Welcome messages + roles |
| `afkCheck.ts` | `messageCreate` | AFK clear + mention notify |
| `voiceStateUpdate.ts` | `voiceStateUpdate` | Join-to-create lifecycle |

## Components

Interactive UI lives in `src/components/`:

```
components/
├── setup/     welcomeComponents, ticketSetupComponents, jtcSetupComponents, setupComponents
└── tickets/   ticketComponents (panel, modal, close button)
```

discordx decorators:

- `@SelectMenuComponent`, `@ButtonComponent`, `@ModalComponent`

Setup flows call `denyUnlessManageGuild()` from `src/utils/setupGuard.ts`.

## Services layer

Business logic and Prisma access are grouped under `src/services/` (e.g. `economyService`, `botStaffService`, `setupService`, `afkService`, `xpService`, `badgeService`).

Prisma client: `src/utils/prisma.ts` (generated client under `src/generated/prisma`).

## Data migration

One-time Mongo import: `scripts/migrate-mongo.ts` → `src/migrator/` (legacy Doubt-Discord-Bot collections → Postgres models).

## Legacy reference

[Doubt-Discord-Bot](https://github.com/Doubt-Productions/Doubt-Discord-Bot) used `ExtendedClient`, manual validators under `src/events/validations/`, Express on port 8080, and Mongo-backed Prisma. That layout is **not** used in doubt-bot; see [Engineering Guide](/reference/engineering-guide) for cutover notes.

## Testing

`tests/*.test.cjs` lock behaviors such as **no Message Content Intent**, staff ACL ≠ badge, and boot command deploy expectations — run with `yarn test`.
