## Development setup

See [Getting Started](/get-started/getting-started). Quick path:

```bash
git clone git@github.com:Doubt-Productions/doubt-bot.git
cd doubt-bot
yarn setup
cp .env.example .env   # fill Discord + DATABASE_URL + DEVELOPER_DISCORD_IDS
yarn dev
```

## Scripts

| Script | Description |
|--------|-------------|
| `yarn dev` | Run bot with tsx (`src/dev.ts`) |
| `yarn watch` | Nodemon + dev |
| `yarn build` | `tsc` → `build/` |
| `yarn start` | `node build/main.js` |
| `yarn setup` | Install, generate, `migrate dev` |
| `yarn setup:prod` | Prod install, generate, `migrate deploy` |
| `yarn lint` / `yarn lint:fix` | Biome check / fix |
| `yarn format:fix` | Biome format |
| `yarn test` | `node --test tests/**/*.test.cjs` |
| `yarn migrate:mongo` | Legacy Mongo → Postgres import |

## Adding a slash command

Create a class under `src/commands/categories/<category>/`:

```ts
import { Discord, Guard, Slash } from 'discordx';
import { Category } from '@discordx/utilities';
import { GuildOnly } from '../../../utils/guildGuards.js';

@Discord()
@Category('Utility')
export class ExampleCommand {
  @Slash({ description: 'Example', name: 'example' })
  @Guard(GuildOnly)
  async example(interaction: CommandInteraction): Promise<void> {
    await interaction.reply({ content: 'Hello!', ephemeral: true });
  }
}
```

Ensure the file is picked up by `importx` (under `src/commands/`). Assign `@Category()` so `/help` lists the command.

### Guards

- `@Guard(DeveloperOnly)` — `/botstaff`
- `@Guard(StaffOnly)` — `/badge` administration
- `@Guard(GuildOnly, ManageGuildOnly)` — `/setup`

## Adding components

Use discordx component decorators in `src/components/`:

```ts
@ButtonComponent({ id: 'my-button' })
async handle(interaction: ButtonInteraction): Promise<void> { … }

@ModalComponent({ id: 'my-modal' })
async submit(interaction: ModalSubmitInteraction): Promise<void> { … }
```

Call `denyUnlessManageGuild()` for setup flows when appropriate.

## Database changes

1. Edit `prisma/schema.prisma`
2. `yarn prisma:migrate:dev --name describe_change`
3. `yarn prisma:generate`
4. Use `prisma` from `src/utils/prisma.ts` in services — keep command handlers thin

Follow Prisma conventions: relations on both sides, `@updatedAt`, indexes on queried fields.

## Testing

```bash
yarn test
```

Tests are Node's built-in runner (`.test.cjs`). They should not require live Discord or Postgres unless explicitly integration-scoped.

Existing regression coverage includes:

| Test | Focus |
|------|--------|
| `no-message-content-intent.test.cjs` | Intent list excludes Message Content |
| `staff-acl-not-badge.test.cjs` | Badge ≠ staff privilege |
| `badge-reserved-lookalike.test.cjs` | Reserved badge key blocking |
| `boot-command-deploy.test.cjs` | Normal boot does not clear guild commands |

Add focused tests when changing ACL, badge rules, or intent configuration.

## Code style

- **Biome** replaces ESLint/Prettier — run `yarn lint:fix` before PRs
- **ESM** — use `.js` extensions in TypeScript import paths where required
- **Services** — prefer `src/services/*` for Prisma and business rules
- **Errors** — use `responseEmbed` / `ResponseType` helpers for consistent replies

## Pull requests (doubt-bot)

1. `yarn test` and `yarn lint` (and `yarn build` for non-trivial changes)
2. Include migration files when schema changes
3. Update [Doubt-Productions/docs](https://github.com/Doubt-Productions/docs) when user-facing behavior or env vars change — not Doubt-Discord-Bot/docs

## Pull requests (docs repo)

Edit MDX in this repository; keep operator docs aligned with doubt-bot `main`. Mention legacy-only behavior explicitly until cutover completes.
